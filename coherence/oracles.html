Oracles in use

Each project below checks its output against an oracle, something to agree with. A row names what the project compares itself against, how, and when the comparison runs. The rows are sorted by how soon each comparison reports: one that runs on every change speaks before the change lands, and one that runs before a release speaks long after the change that broke it.

The holds whose instances this table lists: Drift checks and twin suites (Two copies drift apart); Oracles, mutants and control cases (Green but wrong); Suppressions that expire (A check is silenced instead of satisfied)

Where a project's docs say what keeps a comparison's result meaning what it says, the row lists it by discipline. A discipline a row does not list is not stated either way.

A row may carry probes: a string that a named file, check script or CI step of the repo must have, or must not have, for the row to still be true in the way a file can show. The tests of this site check the ones about a check script or a CI step against its snapshot of the repos, and the evidence task checks the ones about a file. A probe that passes says the file, script or step still has the text the row depends on. It does not say the check is sound. A probe reads only the text it names, so one that says a step is absent does not see the same thing reached through another script or switched on by an environment variable.

  • Every change In the gate a session runs before landing, and again in CI.
  • CI In CI on a push to the main branch or a pull request, and not in the local gate.
  • Release Before a release, and not on each change.
  • On demand When someone chooses to run it.

  • Reference An independent implementation that already has the right behavior.
  • Suite A test suite or recorded baselines from outside the implementation under test.
  • Twin Two implementations in this stack built to match.
  • Build The same source built or run two ways.
  • Law A property the output must satisfy.
  • Previous An earlier version of the same thing.
  • Scoped What the project does not mean to match is named and taken out of the result.
  • Pinned The other side is held to one version, so it changes only when someone changes it.
  • Run live An expectation is checked against the other side as it runs, not only a recording.
  • Sorted A difference is put into a kind before it is counted.
  • Cataloged A difference kept on purpose is listed, and the list is held to the comparison.
