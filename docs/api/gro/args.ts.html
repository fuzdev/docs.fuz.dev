merge_forwarded_args
#

args.ts view source

(args: Args | undefined, forwarded: Args): Args import {merge_forwarded_args} from '@fuzdev/gro/args.js';

Merges forwarded args over args, moving each forwarded key after every key of args. args_parse resolves a no-x pair given both ways to the later key, so a forwarded --color overrides a direct -C (an alias of no-color), where a spread keeps the overridden key at its original position. Keys match by spelling, not by schema alias, so a forwarded alias (-n) doesn't displace a direct canonical key (--name), which args_parse prefers.

args

the direct args, if any, not mutated

type Args | undefined

forwarded

the args forwarded to this command, which win over args

type Args

returns

Args

a new object with the keys of args not in forwarded, then the keys of forwarded

(raw_rest_args?: string[]): Record<string, Args | undefined> import {to_forwarded_args_by_command} from '@fuzdev/gro/args.js';

Parses each Gro task section of raw_rest_args, those after a -- whose first arg is gro, into args keyed by gro and the task name: -- gro test --a is keyed gro test, and -- gro task src/lib/x.task.ts --a is keyed by gro task and the normalized path. Other sections are left verbatim for outside tools, see to_forwarded_argv. When a task has several sections, the last one wins.

to_task_args

(argv?: string[]): CliTaskArgs import {to_task_args} from '@fuzdev/gro/args.js';

Parses the task and its args from process.argv, ignoring anything after any --. gro task <path> consumes one more positional, the path, and refuses a flag before it. gro run [--help] <path> ...rest refuses any other flag before the path and appends the path and rest verbatim to the positionals, unparsed and including any --, so the script gets exactly what follows its path.

type string[]
optional default process.argv

returns
