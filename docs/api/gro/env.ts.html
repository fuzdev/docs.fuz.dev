load_from_env
#

env.ts view source

(key: string, paths?: string[]): string | undefined import {load_from_env} from '@fuzdev/gro/env.js';

Loads a single env value without merging it into process.env. Searches process.env, then each of paths that exists, by default only the cwd's .env - never a parent directory's, so one directory's .env isn't a secret channel to every repo under it. Empty strings are semantically the same as undefined for more ergonomic fallbacks.

resolve_env_vars

env.ts view source

(variables: EnvVarDeclarations, visibility: EnvVisibility, env: Record<string, string | undefined>): Record<string, unknown> import {resolve_env_vars} from '@fuzdev/gro/env.js';

Resolves the declared env vars of one visibility from env, validating each the way SvelteKit does: a var with no schema must be present, and one with a schema gets its Standard Schema result, so validators can transform values and make them optional.

variables

type EnvVarDeclarations

type EnvVisibility

returns
