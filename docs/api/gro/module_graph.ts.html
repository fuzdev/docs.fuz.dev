ModuleGraph import type {ModuleGraph} from '@fuzdev/gro/module_graph.js';

The project's module graph: which files exist under the watched directory and which import which. Tasks and plugins get one on their context. Queries load the graph on first use, and close tears it down for good. A load that fails stays failed: later queries reject with the same error.

Gets the ids of the project modules that exist on disk.

dependents

Gets every module that imports id, directly or transitively. The filter narrows the results, not the traversal. A file reached by a bare specifier is never read, so its imports aren't edges.

watch

Subscribes to changes of project modules, first calling on_change with an add for each module already in the graph. Changes are content-based, so saving a file unchanged emits nothing.

type (on_change: FileChangeCallback): Promise<() => Promise<void>>

close

Stops watching and drops the graph. A graph that never loaded closes without loading. Closing is permanent: later queries and watches reject, as do any pending when it's called. A watch pending when it's called may already have delivered its initial adds before rejecting. Every call returns the same teardown, so an awaited close means fully closed.

type (): Promise<void>

returns Promise<void>

WatchOptions

module_graph.ts view source

WatchOptions import type {WatchOptions} from '@fuzdev/gro/module_graph.js';

What a ModuleGraph and Watcher watch, from GroConfig.watch.

dir

The directory to watch, which holds the project modules. Files outside it enter the graph only when a project module imports them.

type PathId

filter

Excludes the paths it rejects from the change events and from the project modules. It's called with absolute paths, unlike GroConfig.search_filters, which get paths relative to the project root. It filters events, not the directory walk: a rejected directory is still watched, so each path below it is filtered on its own.

type (PathFilter) | null
