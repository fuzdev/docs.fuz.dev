FileIndexIgnoreRule
#

diskfile_helpers.ts view source

FileIndexIgnoreRule

type { kind: "fixed"; } | { kind: "git"; paths: ReadonlySet<string>; nested: ReadonlySet<string>; }

import type {FileIndexIgnoreRule} from '@fuzdev/zzz/diskfile_helpers.js';

How the file index decides what it skips under one root — the client's view of the backend filer's IgnoreRule:

  • fixed — by name alone, FILE_INDEX_ALWAYS_IGNORED_NAMES and FILE_INDEX_PLAIN_DIR_IGNORED_NAMES wherever they appear: a plain directory, a registry's root (indexed at its top level), the app directory and the scoped dirs while no open project focuses them, and a focused directory whose project state has no ignored entry
  • git — FILE_INDEX_ALWAYS_IGNORED_NAMES by name; paths, the daemon's ProjectIgnoredJson.paths for that root: relative to it, each ignored directory with a trailing / (the root itself as ./), each ignored file without one; and nested, its ProjectIgnoredJson.nested: the directories holding a repo of their own, which the filer doesn't enter, relative, each with a trailing /

A permanent filer on a git checkout (the app dir or a scoped dir) runs git's rule on the daemon, but its paths aren't on the wire unless a project focuses it, so here it reads as fixed: a tracked dist/ in it is indexed but hidden in the tree, and a file git ignores there reads as broken in a link, and is waited for, without a notice, when created.

parse_new_diskfile_name
#

diskfile_helpers.ts view source

(name: string, kind: "file" | "folder"): Result<{ value: string; }, { message: string; }> import {parse_new_diskfile_name} from '@fuzdev/zzz/diskfile_helpers.js';

Parses a name entered for a new file or folder, a path relative to Diskfiles.new_files_dir (sub/name.ts creates any missing folders). Leading whitespace and slashes are dropped, as is trailing whitespace — like a pasted name's stray space or newline, they're almost never meant. Whitespace inside the name is kept, including around an inner /. Empty, ., and .. segments are left for the backend to normalize (sub/../a.txt creates a.txt). Refused: a blank or whitespace-only name; one that normalizes to the directory itself (sub/..); a whitespace-only segment (it would create a folder named by whitespace); a .. that climbs out of the directory; and for a file, a last segment that's empty, ., or .. (x/, x/., x/y/..), which names a folder, not a file.

name

type string

kind

whether the name is for a file or a folder

type "file" | "folder"

returns

Result

the name to create, or a message saying why it's refused

to_unindexed_part
#

diskfile_helpers.ts view source

(path: string, root: string, rule: FileIndexIgnoreRule): FileIndexUnindexedPart | null import {to_unindexed_part} from '@fuzdev/zzz/diskfile_helpers.js';

The first part of path below root that the file index skips under rule — the backend filer's is_ignored for one root, and the one predicate the file tree, markdown links, and creating a file share. The filer never lists such a path from root, so a link there can't be told broken, and a file or folder created there never shows.

Checks each part from the root down: a name ignored under every rule, a name ignored under fixed names, or under git each folder prefix (a/, a/b/, …) and the path itself in rule.paths, then each folder prefix in rule.nested — the order the filer's walk checks them in. Set lookups, O(depth), never relying on the daemon's sort order. A file entry matches only a file path and a folder entry only a folder, as the filer keeps them apart.

path

a normalized file path, or a folder's with a trailing /

type string

root

the root whose filer would list it, with a trailing /

type string

rule

that root's rule

type FileIndexIgnoreRule

returns

FileIndexUnindexedPart | null

the skipped part, null when the index enters it all or path isn't under root
