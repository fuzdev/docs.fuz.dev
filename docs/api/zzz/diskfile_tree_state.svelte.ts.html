diskfile_tree_state.svelte.ts

The file tree as the explorer's tree mode shows it: the expanded folders, the active row the keyboard moves, the inline create in progress, and the visible rows derived from them. Lives on DiskfilesEditor, so the expanded set outlives a switch to the list and back, and any remount of the tree.

The rows come from DiskfileIndex.tree_index, kept in step as files come and go, and only expanded folders are walked: deriving the rows costs what they show, never the size of the index.

DiskfileTreeIndex
#

diskfile_tree_state.svelte.ts view source

import {DiskfileTreeIndex} from '@fuzdev/zzz/diskfile_tree_state.svelte.js';

Each folder's direct children, kept in step one file at a time — a file adds itself to its parent and links each folder to the next one up, the way to_file_directories lists them, so an add or remove costs the file's depth, never the size of the index. A folder is in it while some counted file is under it. Diskfiles links every file up to /, not to its source_dir (whichever root's filer reported it last), so a root nested in another shows under it as a folder (unless it's inside an ignored folder — see to_diskfile_tree_rows), and the outer root keeps its files after the nested one closes. Links are counted, so a folder stays while any file passes through it.

Fed by Diskfiles with the files on disk. Its maps aren't reactive: every change bumps version, which every read tracks, so a reader reruns once per batch of changes — and only add_file and remove_file (a file appearing or going), never a file's content changing.

EXPAND_ALL_BELOW_CONFIRM_FILE_COUNT
#

2000 import {EXPAND_ALL_BELOW_CONFIRM_FILE_COUNT} from '@fuzdev/zzz/diskfile_tree_state.svelte.js';

How many files below a folder make "expand all below" ask first. Expanding shows every file below, and every file change under an expanded folder rederives all the visible rows, so a burst of changes there — a build's output — pays for the whole subtree each time. A judgment, not a measurement: a couple thousand rows is past what a person scrolls through, and a rederive of that many stays small beside the explorer's other per-change passes.

to_diskfile_tree_rows
#

diskfile_tree_state.svelte.ts view source

(roots: readonly string[], source: DiskfileTreeSource): DiskfileTreeRow[] import {to_diskfile_tree_rows} from '@fuzdev/zzz/diskfile_tree_state.svelte.js';

Flattens the tree into its visible rows, in display order: each root (once, however often roots lists it), then — while it's expanded — its folders and files, depth first, folders before files. A chain of folders that each hold only the next one shows as one row labeled a/b/c, whose path is the innermost; it's expanded when every folder in its chain is. Walks only expanded folders.

A folder the file index never enters from the root around it (the source's is_ignored_dir) isn't shown under that root: its files can only come from a root nested inside it — say the app directory inside a project — which shows as its own root. A registry's repo (the source's get_repo) is always a row of its own, never part of a compact one, and an unfocused one is a lazy row with nothing under it.
