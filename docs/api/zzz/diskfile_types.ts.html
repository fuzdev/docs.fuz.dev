DiskfileChangeType

"add" | "change" | "delete"

type "add" | "change" | "delete"

import {DiskfileChangeType} from '@fuzdev/zzz/diskfile_types.js';

What happened to a file the backend indexes:

  • add — it's newly indexed
  • change — its contents, size, or timestamps moved — a touch or a rewrite of the same bytes included
  • delete — it's gone

A notification carries the file's metadata, never its contents, so the frontend takes an add or change as a sign the file may have changed: a file it holds eagerly is read again, any other loses its loaded content (see Diskfiles.upsert).

type "unrequested" | "loading" | "loaded" | "unloadable"

import {DiskfileContentStatus} from '@fuzdev/zzz/diskfile_types.js';

Where a diskfile's content stands — see Diskfile.content_status:

  • unrequested — not loaded, and nothing asked for it yet
  • loading — a read is on its way
  • loaded — Diskfile.content holds it
  • unloadable — the read found no text to load (Diskfile.unloaded_reason) or failed (Diskfile.content_error)
