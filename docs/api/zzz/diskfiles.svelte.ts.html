The records of the files on disk, as the index reports them — not the ones kept for a draft or a tab after a delete (deleted_on_disk) or after leaving the index (uncovered), so pickers offer only indexed files. track_changes

Starts recording the paths handle_change is given. Start it before requesting a file-tree snapshot and pass it to add_initial or reconcile with the snapshot, which is then applied around what filer_change reported while the request was in flight: a reported path keeps what the notification left — the snapshot's entry for it is skipped, and it isn't pruned — so a file deleted meanwhile isn't resurrected and newer metadata isn't reverted.

The two can't be ordered from here — a notification that arrives during the request may have been sent before or after the backend read its index for the snapshot — but the backend queues a notification for every change to its index, so its notifications converge on the index: if the snapshot was the newer of the two, whatever moved the file past the notification has its own notification still to come, and that one settles it.

upsert

Adds a diskfile for disknode, or updates the existing one at the same path in place — keeping the cell, with its content and editing state. A diskfile kept after a delete (see remove_by_path) is reattached this way when its path reappears on disk, and one kept uncovered (release_uncovered) when the index reports it again.

A disknode carries metadata only — contents come from diskfile_read alone — so for a diskfile already held its content may be out of date: a file held eagerly — with an editing state, or referenced by a DiskfilePart — is read again, keeping its content until the new one lands, and any other drops its content to unrequested, to be read when next needed (ensure_content). A read in flight reads again instead. A read that lands on the same text changes nothing (DiskfileEditorState.check_disk_changes), so a resync that re-sends every file, or a touch, raises no conflict. A new file starts unrequested, and is read right away if a part references it.

ensure_content

Loads diskfile's content (diskfile_read) unless it's settled — loaded, or unloadable — and resolves once it is. Single-flight: callers share the read in flight, which reads again when the file changes on disk meanwhile, resolving with the newer content. Reads are queued, at most DISKFILE_READ_CONCURRENCY at once, the selected file's first, then those open in tabs. Never rejects: a failed read settles the file with content_error.

Writes state when it starts a read, so call it from an event handler, an $effect, or async code — not a $derived or a template expression.

reconcile

Replaces the file tree under roots with a session snapshot's: upserts every snapshot file (like add_initial), and removes each known file under a root that the snapshot lacks, via remove_by_path — so a file with a draft or a tab is kept, flagged deleted_on_disk. A file the index held here no longer covers (is_indexed) — its repo dropped from the registry or unfocused, its project closed — is absent because the snapshot doesn't look there, not because it's gone, so it's released as release_uncovered would: kept for a draft or a tab, flagged uncovered (unflagged in an unfocused repo), else forgotten. Files outside every root are left alone, since the snapshot says nothing about them.

remove_by_path

Handles the diskfile at path being gone from disk.

If it's held (#is_held) — it has a draft (edited in a tab, a file part, anywhere) or a tab — it's kept, flagged deleted_on_disk with its tab and editing state intact, so the user can save it back (recreating the file), or close the tab and discard the draft (see release_if_unneeded). A rename arrives as a delete plus an add, so its tab stays on the old path. If the path comes back on disk, upsert reattaches the same cell. Otherwise it's removed along with its editing state.

release_uncovered

Releases the files known under dirs that the index no longer covers — the focuses a newer project state dropped (Projects), a kind change included, since a checkout's or plain directory's one focus is its root, and a closed project's root — since stopping a filer deletes nothing here. A file still indexed (another focus, another root, a registry root's loose files) stays. Any other is still on disk as far as anything here knows: forgotten with its editing state, unless held — with a draft or a tab (#release). A held one in a repo that's present but unfocused (is_in_unfocused_repo) is kept as it is, unflagged, until the repo is focused again (the focus's files then settle it); any other held one — its entry out of the registry or missing, under a root that's become a registry's, or under a closed project's root — is kept flagged uncovered, until the index reports it again (upsert). Either way it's kept until nothing holds it (release_if_unneeded) and isn't watched meanwhile. A save never writes blind: an uncovered file's sends the disk version it was based on (diskfile_update's expected_hash), and a file deleted on disk's creates it exclusively (create_exclusive), refused if it's there.

update

Writes content to the file at path. The local Diskfile changes only when the resulting filer_change broadcast arrives, not from the response — which carries the written bytes' hash.

With expected_hash — the hash of the disk content the edit is based on (DiskfileEditorState.last_seen_disk_hash, from a read's Diskfile.content_hash or a save's response) — the backend writes only if the file still holds those bytes, else fails with conflict (data.reason disk_changed, ERROR_DISK_CHANGED), writing nothing. null writes over whatever is there.

Refuses, without sending, to write over a known file whose content isn't loaded (Diskfile.content_loaded — not yet, or not loadable): nobody has seen what it would overwrite. Fails with conflict (data.reason content_not_loaded).

How diskfiles.index differs from its cells, each difference described — empty when they agree: the index holds exactly the paths of the cells on disk (neither deleted_on_disk nor uncovered), each with the cell's root, size, and mtime. A cell keeps no ctime, so that isn't compared. Within DISKFILE_INDEX_CHECK_LIMIT cells, also rebuilds the directories and their counts from the records and compares them with DiskfileIndex.directory_paths and DiskfileIndex.directory_counts. Untracked. A scan of every cell and record — for tests and DEV checks.
