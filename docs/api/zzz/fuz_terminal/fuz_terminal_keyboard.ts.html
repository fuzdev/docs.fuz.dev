fuz_terminal/fuz_terminal_keyboard.ts

A browser KeyboardEvent as a GhosttyKeyInput: the physical key from code, the modifiers, the text the key produced, and the key's unshifted code point — plus which keys the terminal leaves to the browser and the OS. Pure functions over the event's own fields (FuzTerminalKeyboardEvent, so tests pass plain objects); nothing here touches the DOM or the module.

The unshifted code point is the key's text when the event shows it — an unshifted key's own text, a shifted letter lowercased — and otherwise the character the key makes on a US layout (FUZ_TERMINAL_US_UNSHIFTED): the browser exposes no layout table every engine has. So on another layout a shifted digit or punctuation key reports its US character, which the Kitty keyboard protocol sends as the key's code.

get_fuz_terminal_key_mods
#

fuz_terminal/fuz_terminal_keyboard.ts view source

(event: FuzTerminalKeyboardEvent, text: string, platform: FuzTerminalKeyPlatform): number import {get_fuz_terminal_key_mods} from '@fuzdev/zzz/fuz_terminal/fuz_terminal_keyboard.js';

The modifiers held, as GHOSTTY_KEY_MODS bits: Shift, Ctrl, Alt, and Meta as super, CapsLock and NumLock from getModifierState. A side bit is set only on a right-hand modifier's own event — a browser says which side of a modifier is held only when it's that key's event.

AltGraph is a layout's third level, not a modifier: when it made the text (Windows reports it as Ctrl+Alt as well), Ctrl and Alt are dropped, so AltGr+Q's @ is sent as @, not as Ctrl+Alt+@.

On macOS Option is the same kind of level: when it made text with neither Ctrl nor Meta held, Alt is dropped, so a German Mac's Option+5 is the [ it types — never Alt+[ (which the alt escape prefix would send as ESC [, the start of a sequence), and under the Kitty protocol's report-all flag a [ the program receives as text. A program can't tell Option was held for it. Option without text (Option+Left), or with Ctrl, stays Alt.

(event: FuzTerminalKeyboardEvent, text: string): number import {get_fuz_terminal_unshifted_codepoint} from '@fuzdev/zzz/fuz_terminal/fuz_terminal_keyboard.js';

The code point the event's key makes without shift, or 0 when there's none to tell (a function key):

  • a cased letter, lowercased: a for A, whatever the layout or the reason it's uppercase (Shift, CapsLock)
  • otherwise, with no Shift, Alt, or AltGraph changing it, the key's own text: the current layout's character
  • otherwise the US layout's character for the physical key — 1 for Shift+! — and for the letters, their letter
  • for a key the US layout hasn't (IntlBackslash, IntlRo, an empty code), the text's own character, lowercased

is_fuz_terminal_copy_key
#

fuz_terminal/fuz_terminal_keyboard.ts view source

(event: FuzTerminalKeyboardEvent, platform: FuzTerminalKeyPlatform): boolean import {is_fuz_terminal_copy_key} from '@fuzdev/zzz/fuz_terminal/fuz_terminal_keyboard.js';

Whether a key is one of the terminal's copy chords, Ctrl+Alt+C and Ctrl+Insert — with no Shift or Meta, and except on macOS. A view copies its selection on one only while the selection takes some of its text; with none the key is the program's, as any other (FuzTerminalState.handle_key). Ctrl+C is always the program's.

C is matched by the layout's character, or, when that's a letter of another script (Cyrillic с, say), by the physical key — never when AltGraph is held, or when Ctrl+Alt made a Latin letter or a symbol, which is a layout's third level typing it (Windows reports AltGr as Ctrl+Alt: Polish AltGr+C types ć). Insert is matched by key, so the numpad's Insert with NumLock off is one too.

On macOS Cmd+C is the platform's copy and passes to the browser (should_fuz_terminal_pass_key), so Ctrl+Option+C and Ctrl+Insert stay the program's.

should_fuz_terminal_pass_key
#

fuz_terminal/fuz_terminal_keyboard.ts view source

(event: FuzTerminalKeyboardEvent, platform: FuzTerminalKeyPlatform): boolean import {should_fuz_terminal_pass_key} from '@fuzdev/zzz/fuz_terminal/fuz_terminal_keyboard.js';

Whether the browser and the OS keep a key rather than the terminal: any combination with Meta (the OS's and the browser's shortcuts — on macOS, copy and paste among them), Ctrl+Shift+C and Ctrl+Shift+V, reserved for copy and paste, and, except on macOS, the browser's page zoom: Ctrl with =, +, -, _, or 0, Shift or not, the numpad's +, -, and 0 included. The program never sees these; every other key the encoder has bytes for is the program's, Tab, Escape, Ctrl+C, Ctrl+W, and Ctrl+digit included — except a copy chord while there's a selection to copy (is_fuz_terminal_copy_key).

C and V are matched by the layout's character, or, when the layout's isn't a Latin letter (Cyrillic, say), by the physical key. The zoom keys are matched by the layout's character alone, so they follow it to whichever physical key types it; a layout that types one only with AltGr (Ctrl and Alt held, as Windows reports it) leaves it the program's. On macOS the browser zooms with Cmd, a Meta combination, so Ctrl with these stays the program's.
