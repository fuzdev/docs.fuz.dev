fuz_terminal/ghostty_paste.ts

Pasting text into a terminal: libghostty-vt's paste encoder and its safety rule, under the terminal's bracketed paste mode (2004).

GhosttyTerminal.encode_paste is the entry: it reads the mode, applies get_ghostty_paste_hazard, and encodes with ghostty_paste_encode, which replaces the control bytes xterm strips from a paste (NUL, BS, ENQ, EOT, ESC, DEL, and the tty's special characters: Ctrl+C, Ctrl+\, Ctrl+U, Ctrl+Z, Ctrl+Q, Ctrl+S, Ctrl+W, Ctrl+V, Ctrl+R, Ctrl+O) with spaces, then frames the text in ESC [200~ … ESC [201~ when the mode is on, or turns each newline into a carriage return when it's off. Every change is an ASCII byte for an ASCII byte, so the encoded length is known before encoding (to_ghostty_paste_length). Nothing is sent: the caller sends the bytes, as it does a key's.

The library's own ghostty_terminal_paste makes the same bytes — with no clipboard read effect registered (the binding registers none), a Kitty paste event (mode 5522) never happens — but it reads its text through a callback and streams the result through write_pty; encoding here hands the caller the whole result, to measure before anything is sent.

get_ghostty_paste_hazard

(text: string, bracketed: boolean): GhosttyPasteHazard | null import {get_ghostty_paste_hazard} from '@fuzdev/zzz/fuz_terminal/ghostty_paste.js';

Whether pasting text could inject commands, and why: the library's terminal-aware rule (isSafeWith in its input/paste.zig, which ghostty_terminal_paste applies before it encodes). Bracketed, only the end sequence is unsafe; unbracketed, a newline or carriage return is too. The rule is checked on the text as given, before the encoder replaces its control bytes. Unbracketed text holding both is reported as line_break: that's what runs commands as the text arrives, while the end sequence's ESC is replaced by the encoder. Only whether the text is safe is the library's; which hazard is named is the binding's.

ghostty_paste_is_safe is the library's state-free form, the unbracketed rule in every mode.

What GhosttyTerminal.encode_paste made of the text:

  • encoded - the bytes for the PTY, whether they're bracketed, and their length (to_ghostty_paste_length)
  • empty - there was no text, so there's nothing to send
  • rejected - the text could inject commands and that risk wasn't allowed (GhosttyPasteOptions.allow_unsafe); nothing was encoded, and length is what the encoded text's would be

GhosttyPasteHazard

GhosttyPasteHazard

type "line_break" | "paste_end"

import type {GhosttyPasteHazard} from '@fuzdev/zzz/fuz_terminal/ghostty_paste.js';

Why a paste is refused unless allowed:

  • line_break - the text holds a newline or a carriage return and the paste isn't bracketed, so each one reaches the program as Enter — a shell runs the line before it
  • paste_end - the text holds GHOSTTY_PASTE_END, which would let what follows it escape a bracketed paste and run as typed (refused in either mode: text carrying it is suspect whatever the mode, though the encoder replaces its ESC either way)

How GhosttyTerminal.encode_paste treats the text.

allow_unsafe?

The risk the person pasting confirmed (a rejected encoding's hazard and mode): text with that hazard, in that mode, is encoded rather than refused. A confirmation covers only what the person was asked, so unsafe text whose hazard or mode differs now — the program toggled bracketed paste since — is rejected again, with the hazard as it is now. Safe text is encoded whatever this says. Defaults to null: unsafe text is rejected.

to_ghostty_paste_length
#

fuz_terminal/ghostty_paste.ts view source

(text: string, bracketed: boolean): number import {to_ghostty_paste_length} from '@fuzdev/zzz/fuz_terminal/ghostty_paste.js';

The length of text encoded for a paste, in UTF-16 code units of the encoded bytes decoded as UTF-8 (a JS string's length), known without encoding. The text's UTF-8 is its length in those units (a lone surrogate becomes U+FFFD, one unit either way); the encoder changes only ASCII bytes, each to another (a control byte to a space, unbracketed a newline to a carriage return), never a byte of a multi-byte sequence; and bracketed, the frame adds GHOSTTY_PASTE_FRAME_LENGTH.
