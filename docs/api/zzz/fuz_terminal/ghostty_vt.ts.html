fuz_terminal/ghostty_vt.ts

The libghostty-vt wasm module, loaded: Ghostty's terminal emulator compiled to WebAssembly, under a binding that runs in Node and browsers alike — no DOM, no Svelte.

load_ghostty_vt takes the module's bytes (or a fetch Response, or a compiled module) from its caller; this library never fetches an app path itself. The result, a GhosttyVt, holds the instance, its type manifest, its memory, and its build info; handles such as GhosttyTerminal are made from it.

GhosttyVt
#

fuz_terminal/ghostty_vt.ts view source

import {GhosttyVt} from '@fuzdev/zzz/fuz_terminal/ghostty_vt.js';

A loaded libghostty-vt instance. Every handle made from it lives in its linear memory; instances share nothing.

An exception that escapes a call into the module — a trap, or the JS stack running out inside its frames or at a callback boundary — unwinds past the frames' epilogues, leaving the stack pointer kept in linear memory moved, a write abandoned mid-parse, and possibly the shared heap mid-allocation. So every function export is guarded once, here: the first escape poisons the module instance (GhosttyVt.poisoned) — every GhosttyVt wrapping it sees the same poison. The exception reaches the caller of the call it escaped from unchanged (cleanup on its way out skips its calls in), and every later call throws GhosttyPoisonedError before entering wasm. A GhosttyTerminal.write or resize during which a nested call poisoned the instance throws GhosttyPoisonedError too, and no effect handler runs once it's poisoned. A stack overflow at a call's very entry poisons as well, though it disturbed nothing: the guard can't tell it from one that did. An effect handler's own exception doesn't escape — the terminal catches it inside the callback — so it never poisons.

exports

The exports, for the binding's own modules: each function guarded as above, the memory, table, and globals as they are. A function that replaces an export before the instance is wrapped (a test's stand-in) is guarded the same way, so a throw from it poisons too.
