markdown_outline.ts

Where the reader is in a markdown document, for the markdown view's outline: which sections the pane being read shows (to_onscreen_sections), and, with no caret to say, which one the reader is at (to_followed_heading). Pure — the view feeds them its panes' measurements once per frame, so a test needs no layout.

A heading's section runs from the heading to the next heading at its level or above, or to the document's end (to_markdown_sections), so sections nest as headings do: a parent shows while any of its children does.

to_followed_heading
#

markdown_outline.ts view source

(count: number, heading_top: (index: number) => number | null, view_top: number, view_bottom: number, current: number, onscreen: ReadonlySet<number>): number import {to_followed_heading} from '@fuzdev/zzz/markdown_outline.js';

The heading the reader is at when no caret says — the outline's brightly lit item in the preview alone: the topmost heading fully in the pane. Going down, the next heading takes over as soon as the current one starts to leave the top; going up, the previous takes over once its heading is back in view, so the outline never points at a heading the reader can't see. With no heading in view, the current one holds while its section still shows, else the innermost section showing takes over.

Nothing is held back at the very top: the document's first heading in view is current there too, since the outline has no entry for what's above it.

to_visible_source_range
#

markdown_outline.ts view source

(count: number, measure: (index: number) => MarkdownMeasuredRange | null, view_top: number, view_bottom: number): MarkdownSourceRange | null import {to_visible_source_range} from '@fuzdev/zzz/markdown_outline.js';

The source range a pane shows between the content ys view_top and view_bottom (its scrollTop, and that plus its clientHeight): from the start of the first item whose bottom is below view_top to the end of the last whose top is above view_bottom, so an item partly in view counts. The items — the preview's leaf blocks, or the editor's characters, each measured on its line — run down the pane in source order, their tops and bottoms each non-decreasing, so two binary searches measure a few of them, not all.
