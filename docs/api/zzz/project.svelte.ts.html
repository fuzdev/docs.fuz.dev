import {Project} from '@fuzdev/zzz/project.svelte.js';

An open project: a root directory the daemon serves — one scoped root — and the directories in it that are focused, which its file index covers. Keyed by root. Focus is the daemon's, shared by every client, and lasts until it's unfocused (unfocus_repo, a registry's entries only) or the project closes.

ProjectIgnoredJson
#

value + type

{ paths: string[]; nested: string[]; resyncs: number; } import {ProjectIgnoredJson} from '@fuzdev/zzz/project.svelte.js';

What the file index leaves out under one focused directory on git's rule: the daemon's answer, which replaces the client's fixed names there.

paths

Relative to the directory, sorted: each directory git prunes whole with a trailing / (the directory itself, ignored whole, as ./), and each file it skips alone without one.

The daemon sorts by Rust's byte order, which differs from JS string order (UTF-16 code units) for non-BMP characters, so the client looks paths up in a set (Project.ignore_rules, read by to_unindexed_part), never by binary search on this order.

type string[]

nested

The directories holding a repo of their own — a nested repo, a submodule, populated or not — which the daemon doesn't index and git's paths never name: relative to the directory, sorted, each with a trailing /. Read by to_unindexed_part as a nested part.

type string[]

resyncs

Bumped each time the daemon re-pruned the directory without sending a filer_change per file — too many changed at once (a node_modules/ un-ignored) — so a client seeing it move pulls the directory's files whole (repo_files).

type number

focused

The focused directories, each indexed whole, sorted. Opening a path focuses the repo holding it, and repo_focus / repo_unfocus a registry's entries one by one; a checkout's or plain directory's root is its one. A registry's root is indexed at its top level alone, so an unfocused entry has no files.

ProjectRev
#

project.svelte.ts view source

value + type

number import {ProjectRev} from '@fuzdev/zzz/project.svelte.js';

A lifecycle rev: the daemon bumps it on every change to its open projects and stamps it on what changed, so a client applies a project's state only when it's newer than the state it holds, whatever order replies and notifications arrive in. Seeded from the clock (microseconds since the epoch) at boot, so revs keep increasing across restarts; below 2^53, so exact as a JSON number.

Whether every indexed directory of an open project has a file watch. degraded means the OS ran out of watches (inotify's max_user_watches), no watcher could be created, or a directory went missing: the directories without a watch are rescanned every few seconds, so their changes show up late.
